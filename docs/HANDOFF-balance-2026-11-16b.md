## 三、三个候选根因（按可能性排序，带数字）

### 3.1 【已解决，勿再翻】速度环误差方向

- **正确：`speed_err = speed − target`**（即 `pitch_set = trim − err·KP − int`）
- 物理：`pitch_set` 是**稳态目标倾角**。速度环带宽远低于 pitch 环，工作在稳态区，
  稳态 `pitch → pitch_set`，`pitch_set` 越正 = 前倾越多 = 向前加速（`a = g·tan(pitch_set − θ₀)`）。
- `thrust = KP·(pitch − pitch_set)` 只说明「**瞬态**同一 pitch 下 pitch_set 越负推力越大」，
  **不能拿瞬态关系推稳态** —— 这是 `docs/11.14.md` §G 与旧注释的错误所在。
- 证据：HEAD `c130591`（提交信息「零度稳定维持平衡状态」）就是 `pitch_set = trim − speed·(kp+int)`，
  `target=0` 时与现在**逐位等价**。
- ⚠️ 旧的记忆/文档里「改前原式在 target=0 时是正反馈」是**错的**：它是负反馈，所以车才平衡过。

### 3.2 【当前最大嫌疑】互补滤波 α 与 dt 强绑定，且加速度计对平衡车系统性偏向「直立」

**(a) α 的拐点算错了 10 倍**

$$f_c = \frac{1-\alpha}{2\pi\,\alpha\,dt}$$

| α | dt | $f_c$ | τ |
|---|---|---|---|
| 0.98 | 10 ms（教科书 100 Hz） | 0.325 Hz | 49 ms |
| **0.98** | **1 ms（本工程）** | **3.25 Hz** | 49 ms |
| **0.998** | **1 ms（现在）** | **0.32 Hz** | **499 ms** |

原 α=0.98 是从 100 Hz 的例程抄的，本工程跑 1 kHz → **拐点 3.25 Hz 高于内环交越 1.15 Hz**，
加计变成闭环内的主导项：噪声与线加速度污染直接进 `pitch`，再乘 `KP=3000`
→ **1° 假倾角 = 52 PWM 假推力**。

**(b) 但把 α 压到 0.998 会产生新问题（用户实测 ③ 的直接原因）**

加计权重只剩 0.2%/ms → 姿态估计在运动后只能用 0.5 s 时间常数慢慢爬回绝对参考
→ 用户感受为「**找到平衡点更慢了**」。同时陀螺零偏无有效纠正
（0.0017 rad/s × 0.5 s = 0.00085 rad = 0.05°，还不算大，但长时间会积）。

**(c) 更根本的问题：加速度计对「正在加速的平衡车」系统性报「直立」，偏差恰好等于 −θ₀**

平衡车按 `a = g·tan(θp)` 加速（θp = 相对 θ₀ 的倾角）时：

$$f_Y = g\sin\theta_p - a\cos\theta_p = g\sin\theta_p - g\tan\theta_p\cos\theta_p = 0$$

→ **`acc_tilt = 0`（物理直立）**，而真实 `pitch = θ₀ + θp = −0.0906 + θp`。

所以只要车在加速，加计就把估计值往上拽 **+0.0906 rad**：

$$0.0906 \times 3000 = \mathbf{272\ PWM}\ \text{的假前进推力}$$

而速度环总权限只有 360 PWM（0.12 rad）→ **余量仅 1.3 倍**。
这就是「**被影响仍然会冲出去**」的机理：

```
扰动 → 车动起来 → 加速 → 加计报直立 → pitch 估计被拽正
     → 控制器输出 200+ PWM 前进 → 车加速更多 → 加计仍报直立 ↺
     → 直到速度环积分顶到 ILIM 才勉强拉住（余量 1.3x，扰动一大就突破）
```

**(d) 两条可走的修法**

| 方案 | 做法 | 代价 |
|---|---|---|
| **A. α 取中间值** | 0.998 → **0.99**（fc 1.6 Hz、τ 0.1 s） | 折中，不解决 (c) |
| **B. 编码器加速度补偿** | `ATTITUDE_LIN_ACC_ENABLE=1`，**先把 GAIN 改对**（见 §3.3） | 增加约 0.45° 的 pitch 噪声（×3000 = 21 PWM，可接受） |

> 上一轮我以「噪声大于信号」为由否掉方案 B，**那个判断是错的**：
> 用 k_x=226080 重算，`s_lin_acc` 稳态噪声 ≈ 35 (counts/2ms)/s = **0.077 m/s²**，
> 而需要补偿的信号量级是 0.3~3 m/s²，**SNR ≈ 4~40，可用**。

### 3.3 【确定的 bug，但当前不生效】`ATTITUDE_LIN_ACC_GAIN` 大了 32 倍

```c
#define ATTITUDE_LIN_ACC_GAIN   60.0f   /* LSB 每 (counts/2ms)/s，理论值 417919/k_x */
```

注释里的公式是对的，**字面值 60 是错的**：

$$\text{GAIN} = 835.8 \times 0.00221 = \mathbf{1.848}$$

即 `417919 / 226080 = 1.848`。写 60 会让补偿量放大 32 倍，
`MAX_LSB=800` 会经常削顶 → 一开就废。**开 `LIN_ACC_ENABLE` 之前必须先改这个数。**

### 3.4 【次要但真实】±0.96° 的角死区

起转需 50 PWM，`50/3000 = 0.96°`。在这 0.96° 之内控制输出为零，车是**自由倒立摆**
（时间常数 0.10 s）。每次扰动都先「无控制」地倒近 1°，才突然吃到满增益 → 必然过冲。

**唯一软件解法是抬 KP**（死区 ∝ 1/KP）：

| KP | 死区 | $\omega_n$ | 配 ζ=0.7 的 KD |
|---|---|---|---|
| 3000（现在） | 0.96° | 7.2 | 200 |
| 5000 | **0.57°** | 12.3 | 241 |
| 6000 | **0.48°** | 14.7 | 288 |

⚠️ 用户历史实测：「KD=200 高频抖、KD=100~130 可稳定、KD=50 无法平衡」。
按 §3.2 的分析，那个「高频抖」大概率是 **P 项吃带噪声的 pitch × 3000**，
而不是 KD 本身（陀螺噪声 × 200 仅 ≈0.3 PWM）。α 修好后 KD=200 未必还抖，**需重测**。

### 3.5 【未实现，不是当前瓶颈】

- `PID_TURN_KP` / `PID_SYNC_KP` / `PID_YAW_DAMP` **全为 0**，且
  `Control_PID_Step()` **完全没有引用** `in->target_steer` / `in->target_yaw_rate`
  → 阶段 H 实际未实现，`CONTROL_TEST_STEER` 是死参数，车会自己慢慢转。
- `Control_Update()` 的 `!car_run` 分支**不清速度积分**（台架推车后启动会突跳）。
- `Attitude_Update()` 不检查 `imu_seq`（1 kHz 无条件积分，主循环快时可忽略）。
- 零偏只在 `Attitude_Init()` 标一次，**不要改到 `car_state()` 里调 `Attitude_Calibrate()`**：
  那跑在 TIM5 中断（优先级 3），内部 `HAL_Delay` 依赖 SysTick（优先级 15）
  → tick 冻结 → **死循环挂死整机**。要做只能置标志、主循环消费。

## 四、下一步：可执行实验（每次只改一个变量）

当前 `CONTROL_TEST_ENABLE = 0`（纯站立测试），这是对的，**先别开**。

| 步 | 改动 | 判据 | 若不过 |
|---|---|---|---|
| **1** | `ATTITUDE_ALPHA` 0.998 → **0.99** | 比 0.98 抖得轻、比 0.998 找平衡点快 | 仍抖 → 0.995；仍慢 → 0.985 |
| **2** | 录 10 s 站立：`ch0 pitch` / `ch5 pitch_set` / `ch6 pwm` / `ch7 acc_tilt` | `pitch` 平滑波动 ≤0.5°；`pitch_set` 与 `pitch` 长期不分离 | 若 `pitch` 与 `acc_tilt` 持续分离 → 进第 3 步 |
| **3** | `ATTITUDE_LIN_ACC_GAIN` **60 → 1.848**，再 `LIN_ACC_ENABLE` 1 | 轻推后 `pitch` 不再被拽向 0 | 噪声变大 → `LIN_ACC_ALPHA` 0.02 → 0.01 |
| **4** | `PID_PITCH_KP` 3000 → **5000**，`KD` 200 → **240** | 抗扰动手感明显变硬；死区降到 0.57° | 抖 → 先回 KD，再降 KP |
| **5** | 能稳站后再把 `CONTROL_TEST_ENABLE` 改回 1、`SPEED=60`（=0.133 m/s） | 匀速前进不越跑越快 | `pitch_set` 顶限幅 → 查 §3.1 |

**实验顺序有依赖**：1/3 是「让 pitch 估计对」，4 是「让执行器够快」。先 1 再 3 再 4，
否则改 KP 会把姿态噪声一起放大，结论不可分。

### 判定「冲出去」是哪一种（很有用的分辨法）

| 观察 | 结论 |
|---|---|
| `pwm_common` 撞 ±999 | 内环权限不够 → 抬 KP 或查 trim |
| `pitch_set` 撞 `trim ± 0.12` 且 `speed` 单向增长 | 速度环饱和 → 加计偏置吃掉了权限（§3.2c） |
| `pitch` 与 `acc_tilt` 长期分离 | 加计被污染或门控/α 不当 |
| `pitch` 缓慢单向漂 | 陀螺零偏未被纠正（α 太慢） |

## 七、给下一个 agent 的三句话

1. **`speed_err = speed − target` 是对的，别再改。** HEAD 能平衡那版就是这个方向。
2. **先修姿态估计（α 与 dt 的绑定、加速度计对加速车的 −θ₀ 偏置），再谈增益。**
   现在所有「抖动/抗扰差」的结论都可能是姿态污染的间接表现。
3. **一次只改一个参数**，用户每步都要硬件验证。他明确要求「一步一步做，
   每步必须我自己在硬件上验证可用后才进下一步」。
