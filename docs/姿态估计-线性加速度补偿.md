# 姿态估计：误差来源、补偿方案与控制环用法

本工程 `User/Src/Attitude.c` 的互补滤波（LSM6DSR / SPI3，pitch 轴 = X，倾角由 Y/Z 算）。
只讲姿态相关的原理、参数与控制用法，**不含寄存器配置**。

## 硬件约束（决定方案取舍）

1. **IMU 安装位置不可改**，但尺寸可测 → 杠杆臂补偿只能**用软件做**（§4）
2. **竞速时存在同向持续转弯** → 不能用「往复均值为 0」估零偏（§6.2）
3. **左右并排两轮 + 差速转向**（`speedL/speedR`、`PHL/PHR`）→ 侧倾(roll)靠**转向主动恢复**，
   roll 大小由转向环带宽决定（正常工作 2~5°，转向环没调好会倒）；pitch-only 仍成立（§6.1）
4. IMU 仅 6 轴（无磁力计）→ **heading 必然漂**，平衡控制不需要它（§6.2）
5. **电机无电流采样**（ADC 只有 VBAT + 片内温度）→ PWM 全开环，占空比到推力的增益随
   电池电压变化（3S：满电 12.6 V / 标称 11.1 V，差 12%）（§11.3）
6. **IMU 读取原本在主循环**，刷屏会阻塞十几 ms → 必须搬进中断（§11.1）

## 1. 误差来源

### 1.1 加速度计测的是比力

$$\mathbf f = \mathbf a_{\text{lin}} + g_{\text{body}}$$

直立静止时 $\mathbf f$ 与重力同向，`atan2` 准；一旦车有线加速度，`atan2` 给的是两者**合成**方向。

| 车的水平加速度 | 假俯仰误差 |
|---|---|
| 0.02 g（0.2 m/s²） | 1.1° |
| 0.05 g（0.5 m/s²） | 2.9° |
| 0.10 g（1.0 m/s²） | 5.7° |
| 0.20 g（2.0 m/s²） | 11.3° |

**符号（本工程）**：Y 轴指后 → 静止前倾 θ 时 `acc[1] = +g sinθ`、`acc_tilt = +θ`；
向前加速 $a$ 时 `acc[1]` 减去 $a\cos\theta$ → `acc_tilt` 变小（看起来像后仰）。

### 1.2 ❗关键洞察：加速时误差恰好等于真实倾角

平衡车要维持加速度 $a$，车身必须前倾 $\theta \approx \arctan(a/g)$，而恰好在这个角度下：

$$f_Y = g\sin\theta - a\cos\theta = 0 \quad(\text{当 } a = g\tan\theta)$$

**即：车以平衡所需角度加速时，加速度计报「完全直立」**，误差大小正好等于真实倾角（竞速可达 10~20°）。

两点推论：

1. 竞速段**不能信 `acc_tilt` 的绝对值**；
2. 但误差**有规律** → 可用编码器测得的 $a$ 反推 $\theta=\arctan(a/g)$ 作为第三个独立观测。

### 1.3 杠杆臂项（绕轮轴的旋转）

IMU 高于轮轴 $r$ 时，还会额外感受到：

$$a_{\text{IMU}} = a_{\text{车身}} + \underbrace{\alpha r}_{\text{切向}} + \underbrace{\omega^2 r}_{\text{向心}}$$

**陀螺测角速度与位置无关，只有加速度计受害。** 量级与补偿见 §4。

### 1.4 ❗不能用模长检测线性加速度

$$|\mathbf f| \approx g\left(1+\tfrac12 (a/g)^2\right)$$

0.1 g 的水平加速度只让模长变 **+0.5%**，落在 800~1200 mg 窗口内 → **完全测不出**。
`acc_mg` 只能用在这两处：标定期的静止判据、以及**削顶/冲击检测**（§11.4）；
不能当线性加速度检测器。

### 1.5 符号自洽性：两个符号宏必须同号（**已实测，2026-10-21**）

`Attitude.h` 里 `ATTITUDE_ACC_PITCH_SIGN` 与 `ATTITUDE_GYRO_RATE_SIGN` **都取 `+1`，已经是正确值**。
下面保留推导与实测记录，换 IMU 或换安装方式时按同样步骤重验。

先看一条必须遵守的约束 —— 这两个宏**数学上必然同号**：

取倾角 $\psi=\operatorname{atan2}(f_Y,f_Z)$，机体系右手系。陀螺 X 正向转动时 $Y\to Z$，
而归一化的加速度矢量在机体系里反向转，代入可得

$$\frac{d\psi}{dt} = +\omega_X$$

即「加速度算出的倾角变化率」与「陀螺 X 读数」**同向**：

| 组合 | 结论 |
|---|---|
| 两个都 `+1` 或两个都 `-1` | ✅ 自洽（只决定「前倾为正」还是「后仰为正」） |
| 一个 `+1` 一个 `-1` | ❌ **一定错**：陀螺被反向积分，表现为响应迟钝、纯陀螺模式反向发散 |

**实测记录（本车，LSM6DSR / SPI3）**

用 `User/Src/ImuTest.c` 输出加计倾角与陀螺积分，三个动作的结果：

| 动作 | `atan2(acc[1],acc[2])` | `atan2(-acc[0],√(acc[1]²+acc[2]²))` | `∫gyro_z` |
|---|---|---|---|
| 车头下压（前倾） | **增大** | — | — |
| 向左倾 | — | 增大 | — |
| 向左转（俯视逆时针） | — | — | 增大 |

唯一自洽的解释：**X = 车左侧、Y = 车尾、Z = 上（右手系）**。
校验：绕 +X（指向左）按右手定则转，$\mathbf{Y}$(车尾)$\to\mathbf{Z}$(上)，即车尾抬起 = 车头下压 ✓；
且 $\mathbf{X}\times\mathbf{Y}=\mathbf{Z}$ ✓。

由此得出：

- `atan2(acc[1],acc[2])` 前倾为正 → 与头文件「前倾为正」一致 → `ATTITUDE_ACC_PITCH_SIGN = +1` ✓
- 同号约束 → `ATTITUDE_GYRO_RATE_SIGN = +1` ✓
- 车头俯仰是**绕 X 轴**（不是绕 Y），与 `ATTITUDE_GYRO_PITCH_AXIS = 0` 一致 ✓

⚠️ 若换成 X 指右、Y 指前（aerospace 常见）的 IMU，同一套公式会得到相反的符号 ——
**换 IMU 或重新安装后必须重跑上表三个动作**，不要沿用 `+1`。

## 2. 编码器线加速度补偿（推荐先做）

### 2.1 原理

$$a_{\text{lin}} \approx \frac{d\,v_{\text{wheel}}}{dt}$$

测到 $a_{\text{lin}}$ 后从读数中扣除，剩下的才是重力。

### 2.2 精确反解（不能简单相减）

前向线加速度在机体系的分量是 $(0,\,-a\cos\theta,\,+a\sin\theta)$，与重力项叠加后**同时污染 Y 和 Z**：

$$f_Y = g\sin\theta - a\cos\theta,\qquad f_Z = g\cos\theta + a\sin\theta$$

所以要先按当前估计 $\theta_{\text{est}}$ 算出 $a$ 的分量再从读数里**减掉**：

```c
/* a_lin：沿车体前向的线加速度，单位与 acc 一致（LSB）。假定 §1.5 的两个宏都是 +1 */
float c = cosf(pitch_est), s = sinf(pitch_est);
float y = acc[1] + a_lin * c;
float z = acc[2] - a_lin * s;
acc_tilt = atan2f(y, z) * ATTITUDE_ACC_PITCH_SIGN;
```

用上一拍的 `s_pitch` 当 $\theta_{\text{est}}$ 即可（无需迭代）。

⚠️ **符号联动**：若 §1.5 实测后两个宏改成 `-1`，上面两行的 `+`/`-` 必须**同时反过来**
（`y = acc[1] - a_lin*c; z = acc[2] + a_lin*s;`）。改一半会把补偿量加到读数的两倍处，
表现为「加速时 pitch 摆动比不补还大」。验证：§9 第 5 项。

### 2.3 实现要点

| 环节 | 做法 | 坑 |
|---|---|---|
| 速度来源 | `(speedL + speedR) / 2`，TIM6 **500 Hz**（2 ms/次） | `speedL/speedR` 目前**不是 `volatile`**，跨中断读写要补 |
| 求导 | `a = (v - v_last) / 2ms`，**在 500 Hz 处算完**再零阶保持给 1 kHz | 在 1 kHz 侧直接差分会得到 0 / 满幅交替的锯齿，噪声翻倍 |
| 滤波顺序 | **先对速度低通再求导**，或对 `a` 直接低通 | 先求导再滤波，噪声已被放大 |
| 单位换算 | counts/2ms ×500 → counts/s → m/s → LSB | 需标定（§7） |
| 钳制 | `\|a\| < 0.5 g` 上限 | 防滑移/被卡时补偿过头 |

⚠️ **两个频率别混**：速度/控制环是 **500 Hz**（`CONTROL_DT_S = 0.002`，TIM6），
姿态是 **1 kHz**（`ATTITUDE_DT_S = 0.001`，TIM5）。且 `Control_Init/Control_Update`
**目前根本没被调用**（`main.c` 里没有），接控制环前先补上。

### 2.4 增益标定（不需要物理参数）

**必须让轮子着地滚**（桌面 / 光滑地面 / 滚轴）。平举离地时轮子不转、编码器恒 0，
补偿量恒为零，怎么调都不会收敛。用手固定车身姿态不变，推着整车前后移动：

- 真实 pitch 恒为 0；
- 未补偿时 `acc_tilt` 随推动方向正负摆动；
- 步骤：
  1. **先按 §1.5 把两个符号宏定好**（否则增益一定调不准）；
  2. 开补偿，正负各试：**摆幅变小**的那个符号是对的；
  3. 再调增益到摆幅最小。

⚠️ 只调幅值定不出符号：负增益同样能让摆幅变小 —— 但错号是**把误差放大一倍**，
症状是「加了补偿比不加还晃」。所以必须看**开/关补偿前后的摆幅比**，不是看最小绝对值。

比测轮距/线数/减速比可靠，几分钟完成。

### 2.5 局限

| 场景 | 后果 |
|---|---|
| 轮子打滑、悬空、被卡 | 估计的 $a$ 与真实不符 → 误差被**放大** |
| 编码器丢脉冲 | 求导出现尖峰 → 必须钳制 |
| 车身绕轮轴角加速度 | 切向项 $\alpha r$ 不在补偿范围内（见 §4） |
| 坡道 | 平衡控制**不受影响**：倒立摆的参考本来就是重力方向。只有想要「相对路面的俯仰」时才无解 |

## 3. 完整解：扩状态 EKF（暂不做）

标准两状态 EKF（角度 + 陀螺零偏）**同样解决不了线性加速度** —— 它和互补滤波一样把归一化的 acc 当观测。

需要扩成 4~5 状态：

$$\mathbf x = [\,\theta,\ b_{\text{gyro}},\ a_{\text{lin}},\ v_{\text{lin}}\,]^T$$

并把 `acc_tilt` 的观测噪声协方差设成与 $|a_{\text{lin}}|$ 相关，等效于「把编码器信息以正规方式融合」。

- 优点：理论最优，能自动在「信 acc」和「信编码器」之间加权
- 代价：代码量、调参量、调试难度显著上升
- **不建议现在做**：控制环尚未接线、PID 未调，没有角度误差基准时上 EKF 等于盲调两套参数
- ⚠️ 即便上了 EKF，**yaw 仍不可观测**（无磁力计），heading 依旧会漂（§6.2）

## 4. 杠杆臂补偿（软件做，优先级低于 §2）

$r$ = IMU 到轮轴的**垂直**距离（可测）。平衡车姿态修正时 $\alpha$ 可达 10~20 rad/s²：

| IMU 高度 $r$ | $\alpha=20$ rad/s² 的切向加速度 | 假俯仰（瞬时） | 持续 10 ms 后 | 持续 50 ms 后 |
|---|---|---|---|---|
| 0.20 m | 0.41 g | 22° | 4.1° | 14° |
| 0.10 m | 0.20 g | 11° | 2.0° | 7.0° |
| 0.05 m | 0.10 g | 5.7° | 1.0° | 3.6° |

后两列怎么来的：`ATTITUDE_ALPHA = 0.98` → acc 通道时间常数
$\tau = \alpha \cdot dt/(1-\alpha)$ = **49 ms**，误差按 $1-e^{-T/\tau}$ 进入 `s_pitch`。

推论：

- **短脉冲**（几 ms 的抖动）进不来，`r` 再大也不用管；
- **单向持续**的 $\alpha$（起跑、急刹、摔倒）基本完整通过，$r \geq 0.1$ m 时就是 7~14°，不能忽略；
- 平衡振荡时 $\alpha$ 正负交替，低通会把交替部分抵掉 → 这也是 §4 可以排在 §2 后面的真正原因。

→ 顺序：先做 §2（持续几百 ms 的线加速度，**完全**不被低通衰减），再做 §4。

### 4.1 软件补偿公式（只需测出 $r$）

绕轮轴俯仰时，IMU 除重力外还有两个额外分量：

$$f_Y = \underbrace{g\sin\theta}_{\text{重力}} \underbrace{-\ \alpha r}_{\text{切向}},\qquad
f_Z = \underbrace{g\cos\theta}_{\text{重力}} \underbrace{-\ \omega^2 r}_{\text{向心}}$$

```c
/* 全部换算到 LSB 域，r 用米，g 用 9.80665；假定 §1.5 的两个宏都是 +1 */
acc[1] += alpha_pitch * r / ATTITUDE_ACC_MS2_PER_LSB;        /* 扣切向项 */
acc[2] += omega * omega * r / ATTITUDE_ACC_MS2_PER_LSB;      /* 扣向心项 */
```

⚠️ 与 §2.2 同理：宏取 `-1` 时这两行的符号要一起翻。
⚠️ 必须**先扣杠杆臂、再做 §2 的反解**（杠杆臂项在原始读数上，反解依赖已干净的 acc）。

| 项 | 量级 | 是否值得做 |
|---|---|---|
| 切向 $\alpha r$ | 与 $\alpha$ 同量级，**主导项** | $r \geq 0.1$ m 时必做 |
| 向心 $\omega^2 r$ | $\omega=2$ rad/s、$r=0.1$ m → 0.04 g → 2.3° | 可选（$r$ 大或转速高时做） |

### 4.2 $\alpha$ 从哪来

$\alpha = \frac{d\omega}{dt}$，由陀螺微分得到。**必须滤波**：

```c
omega_lpf += (gyro_rate - omega_lpf) * K;          /* 一阶低通 */
alpha      = (omega_lpf - omega_prev) / ATTITUDE_DT_S;
omega_prev = omega_lpf;
```

| 坑 | 处理 |
|---|---|
| 陀螺噪声被微分放大 | 先低通（K 取 0.1~0.3，τ≈3~10 ms）**再**差分 |
| 差分引入 ~0.5 ms 延迟 | 可接受，切向项本来就是慢量 |
| `alpha` 尖峰 | **必须钳制**（如 ±50 rad/s²），否则会瞬间把 acc 掰歪 |

### 4.3 参数标定（不需要物理推导）

$r$ 用尺子量（IMU 到轮轴水平连线的垂直距离）。补偿量程用一个宏在 LSB 域标定：

把车**抬离地面、固定轮轴**（或让轮子悬空），只让车身绕轮轴前后快速摆动：

- 真实线加速度为 0，只有 $\alpha r$；
- 看 `acc_tilt` 的摆幅：**调增益到摆幅最小**即为正确值。

⚠️ 必须让轮子**离地**：轮子着地时摆动会让车前后移动，混入 §2 的平动项，两者分不开。
⚠️ 这一项**编码器补偿管不到** —— 它是绕轮轴的旋转项，不是整车平动。

### 4.4 硬件不能改时的缓解措施

1. **刚性固定** —— 软垫会让模块自己振荡，比硬连接更糟（唯一还能改的）
2. 若 $r$ 很大，**降低角加速度**：PID 的 $K_d$ 不要过冲、转向不要突跳
3. 把 $r$ 和设备高度记进 §7，换结构时重算

## 5. 竞速：持续加减速

### 5.1 前提：误差规律见 §1.2

车以平衡所需角度加速时，加速度计报「完全直立」，误差恰等于真实倾角。所以竞速段**不能信 `acc_tilt` 的绝对值**，只能靠编码器补偿（§2）与门控（§5.2）。

### 5.2 分工：按加速度大小切换信任源

| 工况 | $\|a\|$ | 策略 |
|---|---|---|
| 定速巡航 | 小 | acc 可信，正常互补滤波 |
| 缓加速 | 中 | 门控降低 acc 权重，编码器补偿生效 |
| 全油门 / 急刹 | 大 | **切纯陀螺短期积分**（几百 ms 内零偏漂移可忽略；弯道除外，见下） |
| 起跑瞬间 | 冲击 | 优先只信陀螺；编码器补偿**确认没打滑**时才叠加 |

⚠️ **§2 做好之后，门控的作用会变小**：加速度已被补偿掉，`innovation` 本来就该很小。
所以门控真正的价值是「**补偿失效时**的兜底」—— 打滑、编码器丢脉冲、§2 的增益标错时，
它会自动把权重压下去，避免把这些错误灌进姿态。**别用门控代替 §2。**

门控形式（创新门控）：

```c
float innovation = acc_tilt - s_pitch;
float w = 1.0f / (1.0f + (innovation * innovation) / (TH * TH));   /* TH 取 0.03~0.05 rad */
```

⚠️ 必须设权重下限（如 `w ≥ 0.02`），否则长时间加速会把零偏完全放飞。
⚠️ 但**入弯时别让权重掉到 0**：弯道里 roll 会把 yaw 速率漏进 `gyro[0]`（§6.4），
纯陀螺积分会积出假 pitch，而弯道恰好是 roll 与 yaw 都最大的时候。

### 5.3 滑移检测（线性补偿用）

编码器求导出的 $a$ 在打滑时完全失真。判据要拿**指令推力**去比：

```c
/* 大 PWM 却没加速度 = 空转/被卡；小 PWM 却有大加速度 = 被外力推动/滑落 */
if (fabsf(pwm_cmd) > PWM_SLIP_HI && fabsf(a_enc) < A_SLIP_LO) → 打滑，禁用编码器补偿
```

⚠️ **不要用** `a_acc = tan(f_pitch) * g` 判滑移：这个式子只在「稳定加速」这一平衡条件下成立，
起跑、急刹、入弯时必然不成立 —— 而这几段正是 `a_enc` 最大、最需要补偿的时候，
用它会在最需要的时候把补偿关掉。

转弯用的滑移判据不同（比的是角速度，见 §6.5）。

### 5.4 零偏不能靠静止标定，要用在线估计

竞速全程不静止 → 上电那 0.5 s 标出的零偏会随电机发热漂移（几十~几百 mdps）。

| 做法 | 适用轴 | 说明 |
|---|---|---|
| **往复均值为 0** | **仅 pitch** | 平衡车俯仰来回摆动 → 对 `s_pitch` 做 τ=10~30 s 低通回灌零偏 |
| **停车重标** | 全部 | 最简单可靠，`Attitude_Calibrate()` 挂在 `car_state()` 停车分支 |
| 温度模型 | 全部 | 工程量较大，暂不做 |

⚠️ **「往复均值为 0」的真实含义要看清**：这个做法等价于「强制长期平均 pitch = 0」，
它顺手把机械安装偏差也标掉了，但在**持续加速**时真实平均 pitch 并不为 0（车一直前倾），
于是它会把这部分当成零偏吃掉 → 表现为长时间加速后角度慢慢偏、车速掉下来。

| 取舍 | 结果 |
|---|---|
| 开这个慢修正 | 有安装偏差也能站，但持续加减速时角度会偏（靠速度环积分兜住） |
| 不开，只靠停车重标 | 零偏不会跑，但竞速全程没机会停车 → 温度漂移会累积 |
| 折中（推荐） | 慢修正只在「加速指令小」时更新，即 `\|pitch_set\| < 阈值` 时允许回灌 |

⚠️ **往复平均不能用于 yaw**：竞速存在同向持续转弯（§6.2），yaw 角速度均值不为 0，低通会把转弯速度当成零偏。

### 5.5 降低对角度绝对精度的依赖

竞速赛道的要求是**速度跟随**，角度只是手段。可以：

- 角度环 $K_p$ 取小，把「角度标定残差造成的稳态偏移」交给**速度环积分**吸收
  （这也是 §5.4 里慢修正要谨慎的原因：两个积分器会抢同一个残差）
- 用 `s_pitch_rate` 做**微分 / 阻尼**，减小对角度精度的敏感度

⚠️ **角度环不能取消**：倒立摆的角度是不稳定模态，只有速率反馈时
$\ddot\theta = (g/l)\theta - K_d\dot\theta$ 恒不稳定，必倒。
「不要求绝对精度」≠「可以不要」，角度仍是主反馈。

代价：抗扰动能力与起步响应变差。属于工程折中，不是「更准的 pitch」。

## 6. 竞速：持续转弯与偏航

### 6.1 好消息：对 pitch 影响很小

本车是**左右并排两轮 + 差速转向**。侧倾(roll)由**转向主动恢复**：
车往右倒 → 向右打方向 → 离心力把车身推回来。这是这类车能站住的根本原因，
所以 roll 不是「被机械结构限制」，而是**被转向环压住的**：

| 状态 | 典型 roll |
|---|---|
| 转向环工作正常、直线巡航 | 1~3° |
| 快速入弯（离心力 + 轮胎侧偏） | 5~10° |
| 转向环没调好 / 打滑 / 速度过低 | 发散 → 倒车（此时反而说明该查转向环） |

- 加计：roll φ 绕 Y 轴，**不进 `acc[1]`**；只让 `acc[2]` 乘 cos φ（φ=10° 时 0.985，pitch 影响 < 0.5°）
- 由上：`atan2(acc[1], acc[2])` 给出的 pitch **几乎不受 roll 影响**
- 所以 **pitch-only 互补滤波在本车上是成立的**，不必强行上三维姿态

⚠️ 陀螺侧不成立：roll 会把 yaw 速率漏进 `gyro[0]`，量级不小，见 §6.4。
⚠️ 「roll 可以控制」意味着它可以（也应该）进闭环，但**执行器仍是转向**，见 §10.1.1。

### 6.2 ❗但 yaw 零偏**无法**用往复平均估计

同向持续转弯时 $\overline{\omega_z} \neq 0$，任何「长时间低通当零偏」的方法都会把转弯速率吃成零偏（1 dps 的误判 → 60 s 后 heading 差 60°）。

且 **6 轴 IMU 无磁力计 → yaw 没有绝对参考**，heading 必然漂。结论：

| 需求 | 可行性 |
|---|---|
| 平衡控制（pitch/rate） | ✅ 完全不需要 yaw 准确 |
| 直线行驶（不做转向闭环） | ✅ yaw 随便漂 |
| **按固定赛道跑** | ✅ 靠**循迹传感器**闭环（灰度/摄像头），不靠 yaw 积分 |
| 转向速度闭环 | ⚠️ 只能用**编码器差分**，见 §6.3 |
| 转角积分（"原地转 90°"） | ❌ 无绝对参考，必漂 |

### 6.3 编码器差分：唯一可用的偏航角速度来源

差速驱动运动学：

$$v = \frac{v_R + v_L}{2},\qquad \omega_z = \frac{v_R - v_L}{L}$$

$L$ = 轮距（可测）。用途：

⚠️ **本工程现有实现与上式不一致**，接入前必须先统一：
- `Control.c` 里 `turn_rate = 0.5f * (speedL - speedR)` → 符号与上式**相反**，且差 `2/L`（量纲是 counts/周期，不是 rad/s）
- `encoder_get_delta_right()` 内部已经取过一次负（`return -dlt`）→ 符号链路共两级，别只改一处
- 验证办法：同向转弯时打印 $\omega_{enc}$ 与 `gyro[2]`，**符号必须一致**，再谈量纲

| 用途 | 说明 |
|---|---|
| **转向环反馈** | 不依赖陀螺，无零偏问题 |
| **滑移检测** | 与陀螺 $\omega_z$ 比对，差太大 = 有一方在骗人（§6.5） |
| **线性补偿的速度来源** | 用 $v=(v_R+v_L)/2$ 在转弯时**依然正确**（车体中心前向速度） |

⚠️ 前提是**不打滑**。竞速在弯道内侧轮容易空转，必须配滑移门控。

### 6.4 横向加速度与 roll 串扰

转弯时离心加速度 $\mathbf a_{\text{lat}} = \omega_z \cdot v$ 指向弯心（横向）：

| 弯道半径 | 速度 | $\omega_z$ | $a_{\text{lat}}$ |
|---|---|---|---|
| 2 m | 2 m/s | 1.0 rad/s | 2.0 m/s² = 0.20 g |
| 1 m | 2 m/s | 2.0 rad/s | 4.0 m/s² = 0.41 g |
| 1 m | 3 m/s | 3.0 rad/s | 9.0 m/s² = **0.92 g**（已到轮胎极限） |

它落在 `acc[0]`（X 轴），**不进 `atan2(Y,Z)`**，所以不影响 pitch。

⚠️ 若 IMU 绕 Z 有安装误差角 $\psi$，横向加速度会漏 $\sin\psi$ 到 Y 轴：$\psi=5°$ 时 0.2 g 的 $a_{\text{lat}}$ 会漏 0.017 g → 1° 假 pitch。

#### ❗陀螺侧串扰（比加计侧严重；roll 由转向环压住，所以弯道务必重视）

IMU 有 roll φ 时，陀螺 X 读到的是两个轴的混合：

$$\omega_X = \omega_{\text{pitch}}\cos\phi \ \pm\ \omega_{\text{yaw}}\sin\phi$$

| 弯道 | roll | $\omega_{\text{yaw}}$ | 假 pitch 速率 |
|---|---|---|---|
| R=2 m，v=2 m/s | 2° | 1.0 rad/s | 0.035 rad/s ≈ 2 °/s |
| R=2 m，v=2 m/s | 5° | 1.0 rad/s | 0.087 rad/s ≈ 5 °/s |
| R=1 m，v=3 m/s | 10° | 3.0 rad/s | **0.52 rad/s ≈ 30 °/s** |

后果集中在 §5.2 的「切纯陀螺」：入弯加速正好是 roll 最大 + yaw 最快的时刻，
积分 0.3 s 就是 8.9° 假角度；同时也吃掉 §10.6 冲击阈值（4 rad/s）的余量。

| 对策 | 说明 |
|---|---|
| 入弯不切纯陀螺 | 保留 acc 权重下限，别让门控在弯道把 acc 权重压到 0 |
| 冲击判据加转向门控 | `\|ω_z\|` 大时抬高冲击阈值 |
| 有 roll 估计时解耦 | $\omega_{\text{pitch}} \approx (\omega_X \mp \omega_{\text{yaw}}\sin\phi)/\cos\phi$ |

> **排查线索**：若「转弯时 pitch 总是固定偏向某一侧」，先查 IMU 安装角，再查 roll 串扰，最后查算法。

### 6.5 滑移检测（转弯用）

```
1) 陀螺侧：omega_gyro = (gyro[2] - s_gyro_bias[2]) * ATTITUDE_GYRO_LSB_TO_RADS
2) 编码器侧：omega_enc = (v_R - v_L) / L      /* 先换成 m/s，见 §7 */
3) |omega_gyro - omega_enc| > SLIP_TH  → 判定打滑
   → 本轮禁用：编码器补偿、转向环积分
```

`SLIP_TH` 建议 0.3~0.5 rad/s。两侧同时不可信时退化到「只信陀螺 pitch、编码器只做速度环」。

⚠️ 两侧的符号与量纲先按 §6.3 对齐，否则这个判据会**恒成立**（永远判打滑）。

### 6.6 持续转弯时建议的控制结构

| 层 | 观测 | 说明 |
|---|---|---|
| 直立环 | `s_pitch` + `s_pitch_rate` | 加计侧不受转弯影响；`s_pitch_rate` 有 roll 串扰（§6.4），弯道别切纯陀螺 |
| 速度环 | 编码器 $v$ | 转弯中 $v$ 仍是车体中心前向速度，可用 |
| 转向环 | **编码器 $\omega_z$**，不用陀螺 | 无零偏，竞速可靠 |
| roll 稳定 | **陀螺 Y**（首选）或加计 roll（需门控） | 与转向环**共用执行器**，必须合并设计（§10.1.1） |

**不要**用陀螺 yaw 做转向积分闭环 —— 同向持续转弯 + 无磁力计 → 误差只增不减。

## 7. 硬件参数（需测量，不可改）

| 参数 | 符号 | 用途 | 单位 | 数值 |
|---|---|---|---|---|
| 轮半径 | $r_w$ | counts/s → m/s | m | 待填 |
| 编码器每转计数 | $N$ | counts → 弧度 | count/rev | 待填（TI12 模式 = 4×线数×减速比） |
| 轮距 | $L$ | 编码器差分算 $\omega_z$ | m | 待填 |
| **IMU 到轮轴垂直距离** | $r$ | **切向/向心补偿** | m | 待填 |
| IMU 到车体中线横向偏移 | $d$ | 转弯时附加离心项（一般可忽略） | m | 待填 |
| IMU 绕 Z 安装角 | $\psi$ | 横向加速度漏到 Y 的量 | ° | 待填（§6.4） |

派生换算：

$$k_v = \frac{2\pi r_w}{N}\ \frac{\text{m}}{\text{count}}\qquad
v\,[\text{m/s}] = k_v \cdot \text{speedL} \cdot 500\qquad
a_{\text{LSB}} = \frac{a\,[\text{m/s}^2]}{1.196411\times10^{-3}}$$

⚠️ `speedL/speedR` 是「**每 2 ms 的计数**」（TIM6 500 Hz），必须 ×500 才是 m/s。
少乘这一步，所有速度和加速度都会差 500 倍。

（`1.196411e-3` = $0.122\,\text{mg} \times 9.80665$，即 acc 的 m/s² 每 LSB）

#### ❗安全联锁（第 6 项，必须先于任何闭环）

标定期间 `Attitude_Update()` 输出 `pitch=0 / pitch_rate=0`，直立环看到的就是「完美直立」。
IMU 没起来时（`imu_read_data` 连续失败 → 快照恒 0 → `acc_mg < 800` → 标定永远 restart）
它就一直返回 0，一旦接线就是**恒定推力冲出去**。

```c
/* Control_Update 开头：没标定完不许驱动 */
if (Attitude_IsCalibrating()) { motor_drive(0, 0); return; }
```

- 配一个超时（如 3 s）报警：`Attitude_IsCalibrating()` 一直为 true 就是 IMU 没通
- `Attitude_Init()` 必须放在 `imu_init()` 之后；否则零快照会被当成静止数据
  （现在只是靠 `acc_mg < 800` 侥幸拦住，不是设计）
- **同时确认 `car_run` 的语义**：它在 `event.c` 里默认 `1`，但 `Control_Update()` 目前没有
  调用点，所以现在电机其实不动；接上控制环后默认值变成「上电就驱动」，必须一起处理

**不改动的部分**：`Attitude_GetPitch/GetPitchRate` 签名、`Attitude_Update()` 的调用周期（1 kHz）。

⚠️ 第 1 项（`Attitude_Init()`）不做的话，姿态相关项全部没有意义：`s_gyro_calibrating` 恒 `false`、
`s_gyro_bias` 恒 0，标定从未启动。
⚠️ yaw 零偏不用新加变量：`s_gyro_bias[2]` 已经由三轴标定算出来了。

## 9. 验证方法（每步的可测判据）

| 步骤 | 判据 | 怎么测 |
|---|---|---|
| 1 符号正确（§1.5） | 前倾 20° 时 `pitch` 为正；快摆时 `pitch` 与 `pitch_rate` 同向 | **已实测通过**（2026-10-21）：前倾→增大，故保持 `+1` |
| 2 标定生效 | `Attitude_IsCalibrating()` 能变 false | 串口打 `cal` 字段；静止 0.6 s 后应为 0。**IMU 没起来时它永远为 true** |
| 3 零偏正确 | 临时屏蔽 acc 项，纯陀螺积分 30 s 漂移 < 1° | 不能只看 `pitch`：3.2 Hz 的 acc 通道会把它锁到 `acc_tilt`，零偏错了也照样收敛 |
| 4 编码器增益 | **轮子着地滚**、手固定车身推行，`acc_tilt` 摆幅最小 | 先验符号再调幅值；离地推时轮子不转、编码器恒 0，调不动 |
| 5 反解符号（§2.2） | 加速时 `acc_tilt` 摆幅**比不补偿更小** | 若更大 → 加减号翻错了（或两个宏只改了一个） |
| 6 杠杆臂增益 | 车**抬离地面**、固定轮轴只摆车身，`acc_tilt` 摆幅最小 | 调 `ATTITUDE_IMU_ARM_R`；轮子着地会引入平动，测不准 |
| 7 补偿有效性 | 匀速加速时 `acc_tilt` 与 `pitch` 差 < 1° | 对比两列 |
| 8 门控有效性 | 急刹瞬间 `pitch` 不出现 >3° 尖峰 | 打 `w` 字段看是否掉到 0 |
| 9 转弯一致性 | 定圆转弯时 pitch 漂移 < 1°/圈 | 看 `pitch` 是否持续单向走；同时对比 `ω_enc` 与 `gyro[2]` 的符号 |
| 10 入弯前馈符号 | 入弯瞬间 `pitch` 下陷减小 | 符号必须实测（重心位置决定正负） |
| 11 中断预算（§11.1） | 1 kHz 中断总耗时 < 200 µs | 空闲 GPIO 翻转 + 示波器，或数 DWT 周期计数 |

⚠️ 所有串口输出用**整数**（`newlib-nano` 无 `%f`）：`rad → 0.1°` 用 `(int)(rad * 572.9578)`。

## 10. 控制环用法（循迹 / 转弯 / 竞速）

回答：**姿态模块算出来的哪些量该进控制环、怎么用、哪些不能用。**
前提：左右并排两轮 + 差速转向 + 6 轴 IMU（无磁力计）+ 自主循迹。

⚠️ 本节全部属于**阶段二**。阶段一（§8.1）没通过之前不要动这里的内容。

### 10.1 可用量清单（按可靠性排序）

| 量 | 来源 | 可靠性 | 在竞速里的角色 |
|---|---|---|---|
| `s_pitch_rate` | 陀螺 X 扣零偏 | **最高**（不受线性加速度影响） | 直立环微分、阻尼、**冲击检测** |
| `s_pitch` | 融合（§2~§4 补偿后） | 高（补偿生效后 ±1°） | 直立环主反馈 |
| `acc_tilt` | 加计 atan2 | 中（加减速时不可信） | 仅作慢修正参考，**不进闭环** |
| `gyro[2]`（yaw 速率） | 陀螺 Z | 中（有零偏，短期好） | **弯道瞬时阻尼**，不能积分 |
| `ω_z`（编码器差分） | 编码器 | 高（不打滑时） | 转向环主反馈；里程计式航向（打滑会漂） |
| `roll` 估计 | 加计 `atan2(acc[0], acc[2])` | 低速时高、过弯时低（横向加速度全落在 X 轴） | **转向环的稳定目标**：roll 就是「该打多少方向」的依据（§10.1.1） |

**❗最该记住的一句**：`s_pitch_rate` 是这辆车最可靠的姿态量 —— 陀螺直接测量、不积分、不受 $a$ 污染。**凡是能用速率解决的就别用角度。**

⚠️ 但「最可靠」只覆盖微分 / 阻尼 / 检测：**角度仍是主反馈**，速率不能替代（§5.5）。
⚠️ 弯道里 `s_pitch_rate` 会被 yaw 速率污染（§6.4），「不受 $a$ 污染」不等于「不受转弯污染」。

#### 10.1.1 roll 是「用转向来平衡」的第二个必须闭环的量

本车左右并排，roll 靠差速转向恢复（§6.1）。这意味着：**转向环不只是走路线，它同时是 roll 的稳定器**。

```
        roll 或 roll_rate
              │
              ▼
      转向环 ──→ 差速 ──→ 离心力 ──→ roll 回正
```

| 做法 | 环 | 说明 |
|---|---|---|
| 用陀螺 Y（roll 速率）做阻尼 | 内环 | **首选**：不受横向加速度污染，只在静止时需扣零偏 |
| 用加计 `atan2(acc[0], acc[2])` 做位置反馈 | 外环 | 低速可信；过弯时被 $a_{\text{lat}}$ 污染，必须用 $\|a_{lat}\| = \|ω_z\| \cdot \|v\|$ 门控降权 |

⚠️ **直接拿 `atan2(acc[0], acc[2])` 闭环而不门控会怎样**：0.2 g 横向加速度就会报 **11° 假 roll**，
0.4~0.9 g 报 22~42° → 系统在过弯时误以为要倒了，猛打反方向 → 直接甩出去。

| 反模式 | 后果 |
|---|---|
| 加计 roll 单环、不门控 | 过弯误判，反向甩尾 |
| 把 roll 环和循迹环简单相加 | 两个环抢同一个执行器（差速），互相顶 |
| 不判 roll | 转向环本身就在稳定 roll，通常不必再加独立判据 |

### 10.2 循迹：四层结构，各层用不同量

竞速形态是**自主循迹**（灰度或摄像头给横向位置误差 $e$）。摄像头（OV7725）目前还没启用，
灰度探头能先跑起来 —— 摄像头 30 fps 的链路延迟会让外环带宽上不去，见下面的延迟一节。

```
   循迹传感器（灰度/摄像头）
        │  位置误差 e（横向偏移）
        ▼
   ①  转向外环：ω_ref = Kp·e + Kd·ė            ← 只算"想要多快转"
        │
        │        ┌── ③ roll 稳定：ω_roll = K_roll·roll_rate
        ▼        ▼        （作为 ① 的**参考修正**，不是独立输出）
   ②  转向内环：差速 = Kp·(ω_ref + ω_roll − ω_measure)
        │  ω_measure 用编码器差分（无零偏）
        ▼
   ④  直立环：pitch / pitch_rate → 共同推力
```

| 层 | 反馈量 | 为什么用这个 |
|---|---|---|
| ① 外环（位置→速率） | 循迹传感器 | 与 IMU 无关 |
| ② 内环（速率→差速） | **编码器 $\omega_z$** | 无零偏、可长期保持 |
| ③ roll 稳定 | **陀螺 Y 速率** | 不受横向加速度污染；与 ① 目的一致（转向本来就在回正 roll） |
| ④ 直立（倾角→推力） | `s_pitch` + `s_pitch_rate` | 与转向解耦 |

⚠️ **① 和 ③ 共用同一个执行器（差速）**，所以 ③ 必须写成「② 的参考修正」（如上图），
不要写成两个独立 PID 再把输出相加 —— 两个积分器会互相对顶，表现为过弯时转向发肉或来回摆。

**传感器延迟（决定外环能调多快）**

| 传感器 | 采样 | 典型链路延迟 | 外环可用带宽 |
|---|---|---|---|
| 灰度（模拟/数字，ADC 直读） | 500 Hz~1 kHz | < 2 ms | 高（几十 Hz） |
| 摄像头 OV7725 | 30 fps（33 ms） | 40~60 ms（含 DCMI→内存→算法） | 低（2~5 Hz） |

外环带宽必须低于延迟的倒数一个数量级，否则必然振荡。**摄像头那条路要先解决延迟再谈竞速。**

**为什么转向内环不用陀螺 yaw**：陀螺 yaw 有零偏、且同向持续转弯无法用均值法消除（§6.2）。用它做积分闭环会越跑越偏。陀螺 yaw 只用于瞬时阻尼（§10.4）。

⚠️ **内环必须带打滑退化**：弯内轮空转时编码器差速**偏大** → 内环以为「已经转够了」→ 少给差速 → 更空转（正反馈）。
`|ω_gyro − ω_enc| > SLIP_TH`（§6.5）时把内环权重降到 0，退化成外环直通差速。

### 10.3 快速转弯为什么要加「速率环」

只有外环（位置 → 差速）时，转向是个**一阶系统**，响应慢、超调大、与 $e$ 的导数无关。
加上速率内环后变成二阶，可以独立调**带宽**和**阻尼**：

| 结构 | 转向响应 | 抗侧风/打滑 | 调参难度 |
|---|---|---|---|
| 仅外环 P | 慢、易超调 | 差 | 简单 |
| 外环 P + 内环 P（速率） | **快且可控** | 好 | 中 |
| 外环 PID + 内环 PI（速率） | 最快 | 最好 | 高 |

**竞速建议：外环 PD + 内环 P（速率）**。外环的 D 项用传感器 $\dot e$，或用 $\omega_z$ 代替（小角度下 $\dot e \approx v \cdot \Delta\psi$）。

### 10.4 陀螺 yaw 的正确用法：瞬时阻尼，不积分

```c
/* 只在短时间内用，输出限幅，绝不累加成航向 */
yaw_damp = -K_yawdamp * gyro_yaw;      /* gyro_yaw = (gyro[2] - s_gyro_bias[2]) * LSB_TO_RADS */
```

| 用途 | 做法 | 为什么安全 |
|---|---|---|
| 入弯瞬间抑制过冲 | `differential -= K * gyro_yaw` | 零偏是常数，减掉后微分项只对**变化**敏感 |
| 检测打滑/甩尾 | `\|gyro_yaw − ω_enc\| > 阈值` | 两个独立源比对（§6.5） |
| 弯中保持稳定 | 阻尼项，不参与积分 | 即使零偏有 1 dps，也只是恒定偏置，不发散 |

⚠️ **绝对不要**做 `heading += gyro_yaw * dt` 然后闭环 —— 同向持续转弯下零偏被当成真实转弯，形成正反馈。

### 10.5 弯道中的直立环：用速率做「入弯预判」

竞速入弯时车身会被横向惯性**推倒一下**（离心力 + 轮胎侧偏），表现为 pitch 突然变化。这是直立环最大的瞬时扰动，也是「入弯摔车」的主因。

```c
/* 入弯瞬间的预判：弯越急、速度越快，需要的额外前倾越大。加到【倾角给定】上，不是推力上 */
pitch_set += K_turn_ff * fabsf(gyro_yaw) * v_forward * sign(期望前进方向);
```

| 优点 | 代价 |
|---|---|
| 减小入弯瞬间的 pitch 下陷 | 需实测调 `K_turn_ff` |
| 只依赖 yaw 速率的**绝对值**，零偏影响小 | 直线行驶时无作用（`gyro_yaw≈0`） |

⚠️ **`K_turn_ff` 的符号必须实测**：重心高于轮轴时离心力矩让车向弯外倾；重心极低时效应反号。
⚠️ 加在 `thrust` 上会绕开直立环、稀释阻尼（理由同 §10.7.1），两者都要加在给定上。

### 10.6 pitch_rate 的三个竞速用途

| 用途 | 判据 | 作用 |
|---|---|---|
| **冲击检测** | `\|pitch_rate\|` 突增 > 阈值（如 4 rad/s ≈ 230 °/s） | 摔车/撞墙时立刻卸力，防止轮子持续打滑烧电机 |
| **起跑检测** | 从静止开始 `\|pitch_rate\| > 阈` | 不用等编码器（编码器有量化延迟） |
| **推倒预判** | `pitch * pitch_rate > 0` 且都大 | 正往更倒的方向加速 → 提前加大输出 |

⚠️ 冲击阈值必须大于正常行驶峰值（正常摆动约 1~2 rad/s），否则会误触发。

### 10.7 竞速参数配合（角度精度不足时的手段）

| 残差类型 | 表现 | 对策 |
|---|---|---|
| 慢漂（bias 漂移） | 车缓慢往一边跑 | 速度环积分吸收（**必须有**，否则必漂） |
| 加速时 pitch 偏 | 加速瞬间短暂后仰/前倾 | 用 $a$ 做前馈（§10.7.1） |
| 入弯冲击 | 入弯瞬间车身下陷 | §10.5 的前馈 |
| 高频抖动 | 电机嗡鸣 | 降低 $K_d$，或对 `pitch_rate` 加低通 |

#### 10.7.1 加速度前馈（与 §2 的补偿互补）

补偿是「修正观测」，前馈是「修正给定」。前馈要加在**倾角给定**上，不是加在推力上：

$$\theta_{\text{ref}} \mathrel{+}= \arctan\!\left(\frac{a_{\text{desired}}}{g}\right)$$

这正是 §1.2 的平衡条件反解 —— 车要以 $a$ 加速，本来就得倾斜 $\arctan(a/g)$，不是额外开销。
前馈让速度环不必先攒出倾角误差就能产生加速度，响应更快、超调更小。

```
速度环(PI) ──→ a_desired ─→ atan(a/g) ─→ 倾角前馈 ─┐
             │                                      ├─→ θ_ref → 直立环PD → 推力 → 电机
             └──────────────────────────────────────┘             ↑
                                                        s_pitch / s_pitch_rate
```

⚠️ **不要直接把 $u_{\text{ff}} = K_a \cdot a_{\text{desired}}$ 加到 thrust 上**：
那等于给一个不受姿态反馈约束的开环推力，会稀释 $K_d$ 的阻尼，摆起来收不住。
前馈到给定则整条闭环仍然包住它，等价且安全。

（§10.5 的入弯前馈同理：加在 `pitch_set` 上比加在 `thrust` 上安全；
若一定要加在推力上，必须同时按该推力重新设计阻尼。）

### 10.8 哪些 IMU 量**不该**进竞速控制环

| 量 | 为什么不用 |
|---|---|
| `acc_tilt` | 加减速时误差可达 15°，且趋势与真实倾角相反（§1.2） |
| 积分出的 `heading` | 6 轴无磁力计 + 同向转弯 → 必然漂（§6.2） |
| `acc_mg`（模长） | 对水平加速度不敏感（0.1 g 只变 0.5%），不能当加速度计 |
| `atan2(acc[0], acc[2])` 单独闭环 | 过弯被 $a_{lat}$ 污染 22~42°，必须配门控（§10.1.1） |
| 陀螺 X 的**绝对值** | `rate` 可用，但积分成角度后会被 $a$ 污染和零偏共同影响 |

> 本节相关修改项（15~24）见 §8.2。

## 11. 实时链路与遥测（不解决这些，前面全部测不出来）

### 11.1 中断划分：IMU 读取必须离开主循环

现状：`imu_service()` 在 `main()` 里轮询 `imu_drdy_flag`，而主循环还要跑 `KK_UI_AppUpdate()`。
刷一屏 128×160 时主循环会被占住十几 ms，这段时间：

- `Attitude_Update()` 在 1 kHz 中断里**反复积分同一个陀螺样本** → 1 rad/s 就是 15 mrad ≈ 0.9°；
- `s_pitch_rate` 一起变陈旧，控制环拿到的微分项是 15 ms 前的值；
- DRDY 只有 1 bit 标志，1.66 kHz 的样本被静默丢弃。

**建议划分**

| 任务 | 位置 | 频率 | 备注 |
|---|---|---|---|
| IMU 读 12 B（SPI3 @10.5 MHz，≈10 µs） | **TIM5 ISR**（与姿态同频） | 1 kHz（有新数据才读） | 必须改超时机制，见下 |
| `Attitude_Update()` | TIM5 ISR | 1 kHz | 保持不动 |
| 编码器读数 + `Control_Update()` | TIM6 ISR | 500 Hz | 速度与控制同频，避免 ZOH 抖动 |
| 遥测发送 | 主循环 + DMA | ≤500 Hz | 绝不在 ISR 里阻塞发串口 |
| TFT 刷新 | 主循环 | — | 只影响观感，不影响控制 |

⚠️ **IMU 读和姿态用同一个定时器**（TIM5）：如果分成两个不同频率的中断，
姿态会时而在同一个样本上积分两次、时而跳过一个，等效采样率抖动，姿态看起来会「一顿一顿」。

⚠️ 读取时仍按 `imu_drdy_flag` 判断有没有新数据：没新数据就**跳过读**，但姿态照样按 1 ms 积分
（零阶保持是正确行为，不是缺陷）。

**必须改掉的坑**：`imu.c` 的 SPI 超时用的是 `HAL_GetTick()`。在优先级高于 SysTick 的中断里
`HAL_GetTick()` **不再增长** → SPI 一旦卡住就是**死循环**（比超时更糟）。改法：

```c
/* 用计数器上限代替 tick：时间按 CPU 周期折算，与中断上下文无关 */
for (uint32_t n = 0U; (SPI3->SR & flag) == 0U; n++)
{
    if (n > IMU_SPI_SPIN_MAX) { return false; }
}
```

`IMU_SPI_SPIN_MAX` 取「正常等待周期的 10 倍」量级；10.5 MHz 下 12 B 约 10 µs，正常等待 < 200 次循环。

**预算**：F407 @168 MHz，1 kHz 中断里跑 `atan2f` + `sqrtf` + 十几次乘加大约 2~4 µs（有 FPU）。
加上 §2/§4 的 `cosf/sinf` 也远低于 200 µs。**但 EKF（§3）不要放中断**，那是几十 µs 到上百 µs 的量级。

**共享数据**：`speedL/speedR` 现在是普通 `int16_t`，TIM6 写、TIM5 读 → 必须加 `volatile`。
`imu_gyro[]/imu_acc[]` 三个分量的快照也非原子（可能读到跨样本的组合），
若对一致性敏感，改成「1 kHz 中断里一次性拷进本地数组」。

### 11.2 遥测：带宽与帧格式

USART3 现在 115200 8N1 ≈ 11.5 kB/s。**实测观测需求**：一次要 5~6 个量，每量 2~4 字节。

| 方案 | 帧长 | 可用频率 | 评价 |
|---|---|---|---|
| ASCII（`uart_printf`） | 40~60 B | ≤ 100 Hz | 最省事，但 500 Hz 必堵 |
| 二进制帧 @115200 | 16 B | ~700 Hz | 够用，需自己解析 |
| 二进制帧 @921600 | 16 B | 受限于采样率 | 推荐 |
| 二进制帧 @2M + DMA | 16 B | 无限制 | 最终形态，但要先解决 DMA 与 printf 互斥 |

USART3 挂在 APB1（42 MHz），理论最高波特率 ≈ 42 MHz/16 ≈ **2.6 Mbaud**，
所以 921600 甚至 2 Mbaud 都能用 —— 只需要上位机配合。**注意 `huart3.Init.BaudRate` 改完
要确认 CubeMX 不会把它改回去**（`usart.c` 是生成文件）。

二进制帧建议最简结构（和 ESP32 链路保持一致，方便以后复用）：

```
[0xA5][0xA5][len][seq][ 数据: int16 小端 ×N ][ 校验:XOR ]
```

⚠️ **`uart_printf` 是阻塞发送**（`HAL_UART_Transmit`），单次 128 B @115200 要 11 ms。
放在 1 kHz 中断里会直接吃掉 11 个周期 → **遥测一律在主循环发，或改 DMA**。
⚠️ 字段一律用**整数**：`newlib-nano` 没开 `_printf_float`，`%f` 打不出来。

### 11.3 开环 PWM 与电池电压

电机是 PH+EN，`motor_drive()` 只写占空比，**没有电流环**（ADC 只采 VBAT + 片内温度）。
所以：

| 事实 | 后果 |
|---|---|
| 占空比 → 电机电压 = 占空比 × $V_\text{bat}$ | 3S 从 12.6 V 掉到 11.1 V，同样占空比推力小 12% |
| 没有电流/力矩反馈 | 无法判断「给了多少推力」，只能拿占空比当**指令** |
| 无法做力矩限幅 | 堵转时电流只受电机内阻限制，靠软件防不住，只能限时/限温 |

**建议**：把输出写成「等效电压」，而不是「占空比」

```c
/* 按当前电压折算占空比：电压高时自动收一点，低时放一点，等效电压保持不变 */
float vbat  = Analog_ReadVoltage();
if (vbat < V_BAT_MIN) { vbat = V_BAT_MIN; }            /* 不许除零/放大到炸管 */
float scale = V_BAT_NOMINAL / vbat;                    /* 3S 取 11.1f */
int16_t pwm = control_limit(out * scale);
```

⚠️ `vbat` 必须**下限钳制**：上电瞬间 `Analog_ReadVoltage()` 返 0，不钳就是除零 + 无限大输出。
⚠️ 输出上限仍要钳到 `CONTROL_PWM_MAX`，别让满电时溢出。
⚠️ 电压补偿只保证「相同指令 = 相同电压」，**不会**让低压时推力变大 —— 那是物理限制。
不要用「电压低就放大增益」去掩盖，那会烧电机。

### 11.4 量程与饱和检测

现在 ±4 g（0.122 mg/LSB）、±500 dps（17.5 mdps/LSB），是平衡车的常规选择，**保持不变**。

| 情况 | 表现 | 处理 |
|---|---|---|
| 加速度削顶（>4 g） | 落地/撞墙瞬间 `acc` 贴 ±32760 | 用模长判据 `\|acc\| > 3.9 g` 置「冲击」标志，当拍**丢弃 acc 观测** |
| 陀螺削顶（>500 dps ≈ 8.7 rad/s） | 摔车瞬间读数贴边 | 撞击判据（§10.6）用 4 rad/s，留有余量；读数贴边时直接置「已摔」 |
| ±2 g 提高分辨率 | 0.061 mg/LSB | **不推荐**：见下，分辨率本来就不是瓶颈，反而 2 g 就削顶 |

⚠️ 0.122 mg/LSB 在 20° 附近约等于 **0.007°**，量化远细于噪声（零偏抖动、振动都在 0.1° 以上）
—— 所以**没必要为分辨率改量程**，改了只是把削顶风险换成了看不见的改善。
